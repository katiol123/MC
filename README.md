# BONEFORGE — процедурный 2D-файтинг

Аркадный файтинг «улица на пирсе» с двенадцатью бойцами. **Все бойцы и вся их анимация рисуются кодом**:
скелет с иерархией костей → прямая/обратная кинематика → процедурная геометрия тела (мышечные
сегменты на кривых Безье, торс, череп, одежда), cel-shading с контровым светом, контуры, тени.
Ни одного спрайта, sprite sheet или растровой картинки бойца в бою не используется.

Портреты из `assets/portraits/` (присланные концепты) показываются **только** в меню: на экране
выбора бойца, VS-заставке, в иконках HUD и на экране победы. Внешность процедурных бойцов
(причёски, одежда, палитра) сделана по мотивам этих концептов. Музыка боя — присланный трек
`assets/music/steel-tangerines.mp3`; звуковые эффекты синтезируются WebAudio.

## Запуск

**Самый простой способ — открыть `index.html` двойным кликом.** Он подключает `boneforge.bundle.js`:
все модули из `src/`, собранные в один обычный скрипт, поэтому игре не нужен сервер (портреты,
музыка и настройки работают и из `file://`).

Для разработки (Node.js ≥ 18, зависимостей нет):

```bash
npm start            # локальный сервер → http://localhost:8080 (index.html) или /dev.html
npm run build        # пересобрать boneforge.bundle.js после правок в src/
```

`dev.html` грузит ES-модули из `src/` напрямую: правки видны без пересборки, но нужен сервер —
браузеры не загружают ES-модули из `file://`. `npm test` проверяет и то, что бандл не устарел.

Быстрые ссылки для разработки:
`index.html#fight=brick:jax:cpu` (сразу бой; режимы `cpu`, `versus`, `training`, `watch`),
`#select=versus`, а также `tools/gallery.html` — крупный просмотр бойцов и поз
(`tools/gallery.html#fighter=roxy&clips=idle,attack:hk,attack:s3&scale=1.4`).

## Управление

| Действие | Игрок 1 | Игрок 2 |
|---|---|---|
| Движение / прыжок / присед | W A S D | стрелки |
| Лёгкий / тяжёлый удар рукой | F / G | I / O (Num4 / Num5) |
| Лёгкий / тяжёлый удар ногой | V / B | K / L (Num1 / Num2) |
| Смена стойки (ведущая рука/нога) | R | P (Num0) |

* Блок — держать «назад» (от противника); низкий блок — «вниз-назад». Удары с прыжка — overhead
  (их нельзя блокировать сидя), подсечки/лоу-кики — только сидя.
* Рывок — двойное «вперёд» (удерживать → бег), отскок — двойное «назад».
* Приседая: **↓+HP — апперкот** (лаунчер), ↓+LK — лоу-кик, ↓+HK — подсечка (нокдаун).
* Спецприёмы: **↓↘→ + удар рукой** — Surge Fist (рывок-удар), **→↓↘ + рука** — Skybreaker
  (неуязвимый взлетающий апперкот), **↓↙← + нога** — Whirl Kick (разворот, нокдаун).
* **Бросок** — LP+LK вместе (F+V) вплотную: не блокируется. **Тех** — то же сочетание в первые
  9 кадров после захвата: бросок срывается, урона нет. Нельзя бросить противника в прыжке,
  в оглушении/блоке и сразу после подъёма. Удерживая «назад», бросаешь за спину.
* **Фирменный приём** — ↓↙← + рука, у каждого свой (см. ниже).
* **Супер** — ↓↘→↓↘→ + рука, только при полной шкале (внизу экрана). Стоп-кадр с портретом,
  серия ударов. Защита от спама: супер стоит всю шкалу, сам шкалу не копит, и 8 секунд после
  него шкала не растёт; полная шкала ≈ нанести 1000 урона — реально ~1 супер за раунд.
* Комбо: лёгкие удары отменяются в более тяжёлые, обычные — в спецприёмы, **только при попадании или блоке**.
* Отладка: **F1** (или `) — оверлей, **F2** — замедление ×1/×0.5/×0.25/×0.1, **F3** — пауза,
  **F4** — шаг на один тик, **Esc** — пауза-меню. В тренировке **T** меняет поведение манекена
  (стоит / сидит / блокирует всё / прыгает / CPU).

## FINISH HIM и фаталити

В решающем раунде (тот, проигрыш в котором проигрывает матч) смертельный удар не роняет бойца, а оставляет
его шататься: «FINISH HIM!» / «FINISH HER!». У победителя 5 секунд: вплотную ввести **↓ ↘ → ↓ ↘ → + удар ногой** —
и начнётся фаталити. Обычный удар в это время — простой K.O.; если ничего не делать, проигравший падает сам.
CPU сейчас делает фаталити **всегда** (`AI_FATALITY_CHANCE` в `src/ai/aiController.js`).

Фаталити — комичные постановочные сцены (код: `src/fatality/`), каждая написана один раз и работает на любом
сопернике (общий скелет, размеры берутся из пропорций жертвы; автотест прогоняет все 12 × 12 пар):

| Синдер | WELL DONE — огненный столб, обугленный силуэт моргает белыми глазами и осыпается кучкой пепла |

**Критическое здоровье** (ниже 30 %): боец тяжело дышит (плечи ходят, голова и guard опускаются), под глазом
синяк, на брови ссадина, капает пот, и у каждого с анимацией слетает своя деталь — у Бруно колпак, у Раттигана

Предметы кувыркаются, отскакивают от пола и лежат там до конца раунда.

Огонь виден только на фирменном приёме и супере Синдера; его обычные удары — без огня.

Все они описаны данными в `src/data/signatures.js` (шаги серий, снаряды, захваты, контр-стойка,
прыжки) — системы общие, кода «под конкретного бойца» нет.

## Что реализовано

**Архитектура** (`src/`, ES-модули, без сборки; ~40 файлов, самый большой — художник тела):

| Модуль | Ответственность |
|---|---|
| `core/` | математика, детерминированный ГПСЧ, цикл с фиксированным шагом (60 тиков/с, аккумулятор + интерполяция) |
| `config/` | константы движка и `tuning.js` — глобальные правила боя (гравитация, буфер ввода, скейлинг урона, лимиты жонглирования…) |
| `data/` | **данные**: `moves.js` — фреймдата всех атак, `fighters.js` — 12 бойцов (пропорции, статы, внешность, переопределения атак). Баланс меняется здесь, без правки систем |
| `input/` | клавиатура, буфер ввода (нажатие/удержание/отпускание, направления относительно противника, распознавание движений 236/623/214, двойные нажатия) |
| `anim/` | скелет (FK, 2-костная IK ног, ограничения суставов, центр тяжести), ключевые позы, клипы, аниматор (кроссфейды, контроль скорости суставов, зеркалирование стойки) |
| `physics/` | тело бойца (скорость, ускорение, торможение, гравитация, импульс/масса), пушбоксы и стены, ограничение расстояния, инерция конечностей |
| `combat/` | hurtbox/hitbox из костей, регистрация попаданий, блок, контр-удары, трейды/клэши по приоритету, комбо-защита |
| `fighter/` | машина состояний бойца |
| `game/` | матч: раунды, таймер, KO, слоу-мо KO, рестарт |
| `ai/` | CPU-противник (3 уровня), играет через тот же «сырой» ввод, что и клавиатура |
| `render/` | художник тела, вторичная анимация (волосы, дреды, хвост, полы плащей), арена, эффекты, камера, HUD, отладочный оверлей |
| `audio/` | синтез звуков WebAudio + музыка боя |
| `ui/` | титульный экран (на фоне идёт CPU-бой), выбор бойца, VS-заставка, сцена боя, меню, результаты |

**Ключевой принцип — разделение анимации и правил попадания.** Симуляция каждый тик сэмплирует
позу из клипа, считает скелет и строит hurt/hitbox-капсулы на костях. Рендер берёт ту же позу,
интерполирует между тиками и добавляет *только визуальные* слои (инерция конечностей, волосы,
сплющивание при ударе) — хитбоксы от них не зависят.

**Процедурные бойцы.** 23 сочленения, кости: таз, поясница, грудь, шея, голова, плечи, плечо/предплечье/кисть,
бедро/голень/стопа. Конечности — сегменты с выпуклостями мышц (бицепс, икра, квадрицепс), бесшовные
внутри группы (двухпроходная отрисовка: силуэт-контур + цвет), торс — контур по точкам каркаса,
голова — череп+лицо одним силуэтом, глаза/брови/рот/борода/серьги/причёски, одежда восьми типов,
обувь, перчатки, шляпы (цилиндр с гоглами, поварской колпак), маска ягуара, капюшон. Порядок слоёв
меняется при ударах дальней рукой/ногой (данные атаки), при развороте выполняется «сжатие» по X,
у Whirl Kick — имитация оборота. Смена стойки зеркалит ведущие конечности (и хитбоксы).

**Анимация.** Idle с дыханием и переносом веса; ходьба вперёд/назад с IK-стопами, фаза шага привязана
к реально пройденному расстоянию (стопы не скользят — проверено тестом); бег; рывок/отскок; присед;
прыжок на месте и сальто вперёд/назад; приземление; LP/HP/LK/HK, апперкот, лоу-кик, подсечка,
2 воздушные атаки, 3 спецприёма; блок высокий/низкий; реакции на удар (голова/корпус/сидя), стаггер,
отбрасывание, жонглирование, нокдаун с отскоком, подъём; головокружение (dizzy); 4 победные позы,
поражение. Каждая атака: замах → ускорение конечности (кривая strike) → контактная поза ровно на
первом активном кадре → удержание → возврат. Тайминг клипа выводится из фреймдаты, поэтому смена
startup/active/recovery в `moves.js` автоматически перестраивает анимацию. Аниматор ограничивает
угловую скорость суставов и скорость таза — без телепортаций.

**Бой.** Startup/active/recovery, урон, стан-урон, hitstun/blockstun, hitstop, высота (mid/low/overhead),
реакция, толчок, параметры подброса, цепочки и окна отмены, жонглирование, приоритет, неуязвимость
по частям тела — для каждой атаки отдельно. Зоны поражения: голова (×1.1 урона), корпус, конечности.
Контр-удар (+урон/+hitstun, тяжёлый — стаггер), «punish», трейды и клэши, отталкивание атакующего
в углу, chip-урон спецприёмов, головокружение по шкале стана. Защита от бесконечных комбо: скейлинг
урона, затухание hitstun, очки жонглирования + усиление гравитации, лимит длины цепочки, лимит повторов
одного приёма, абсолютный кап ударов в комбо.

**Обратная связь.** Hitstop с дрожанием цели, искры/кольца/вспышка контакта (жёлтые на контр-ударе),
щит блока, «разрез воздуха» при промахе, следы быстрых ударов, тряска камеры на сильных ударах,
пыль при прыжках/приземлениях, белая вспышка тела при попадании, KO-слоумо. Арена «Pier 9»
(закат/ночь): небо с солнцем, 2 слоя города с параллаксом, краны, вода с бликами, контейнеры,
мигающая неоновая вывеска, гирлянды, мокрые доски с отражениями, передний план, туман, виньетка.

## Тесты

```bash
npm test             # node --test: 77 тестов физики, состояний, попаданий, анимации, матча
npm run audit        # аудит: все пары бойцов CPU vs CPU, проверка что каждая механика реально случается в боях
npm run smoke        # браузерный смоук-тест (нужен Playwright: npm i -D playwright)
```

Покрыто автотестами (все проходят): пол не пробивается ни одной частью тела в боях всех 12 бойцов;
прыжки стабильны (одинаковая высота/время); пушбоксы не пересекаются при сближении, толкании,
в углу и после перепрыгивания; выход из угла; ограничение дистанции; удары регистрируются только
в активные кадры (каждая атака каждого бойца + все попадания в CPU-боях); один удар — одно
попадание; hitstop замораживает обоих; блок высокий/низкий/overhead; блок после смены сторон;
контр-удар; отмена только при контакте; мэш-комбо не зацикливается; лимит жонглирования; все
обычные удары попадают в упор; апперкоты (↓+HP и Skybreaker) попадают по каждому сопернику вплотную и на средней дистанции и сбивают прыжки; каждый удар каждого супера попадает по каждому сопернику; поджог Синдера (тики, 10 с, не добивает); буфер ввода, удержание кнопки не повторяет удар; спецприёмы по
движениям; шкала стана → головокружение; переходы ходьба/присед/прыжок/рывок/бег/блок; смена стойки; нокдаун→подъём;
IK ставит стопы точно; длины костей сохраняются; ограничения суставов; нет скачков поз в анимациях
и в реальных боях; стопы не скользят при ходьбе; KO → следующий раунд → конец матча → рестарт;
победа по времени; тренировка без KO; полные матчи CPU vs CPU для всех бойцов; детерминизм;
**одинаковый результат симуляции при рендеринге 30/60/144 Гц**.

Смоук-тест (выполнялся в headless Chromium): меню → выбор → VS → бой, нажатия клавиш, оверлей,
отсутствие JS-ошибок; стоимость кадра в headless-рендере без GPU ≈ 10 мс (≈ 20 мс с включённым отладочным оверлеем), тик симуляции ≈ 0.04 мс.

## Ограничения и что осталось

* Phaser не используется: Canvas 2D напрямую даёт нужные кривые Безье, градиенты и клиппинг для
  процедурных тел без обёрток; архитектура (сцены, цикл, модули) — эквивалентная.
* Бойцы различаются внешностью, пропорциями, статами и параметрами атак, но анимационный набор и
  список приёмов у всех общий (уникальные спецприёмы для каждого — следующий шаг).
* Нет бросков, снарядов, шкалы «супера», онлайна и геймпада.
* Ограничения скорости в тестах анимации (≤70 px/тик для кистей/стоп, ≤50 для корпуса в атаках) —
  осознанный компромисс для быстрых аркадных ударов; хитбоксы всегда идут по фактической позе.
* Шрифт интерфейса — системный (Arial Black/Impact); на системах без них будет запасной sans-serif.
* Производительность замерялась только в headless Chromium без GPU; на реальном железе не проверялась.
* ИИ простой (реакция с задержкой, блок с вероятностью, анти-эйр, наказание промахов, короткие комбо),
  не учит паттерны игрока.
